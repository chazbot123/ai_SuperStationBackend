# 项目规则

## 当前仓库根目录
- 当前 Git 根目录是 `D:\zhilin_project\AI-SuperWeb\AI-SuperWeb`。
- 当前目录外层还套了一层 `AI-SuperWeb`，后续目录迁移目标单独处理，不在本规则中直接执行跨目录移动。

## 目录边界
- 前端主代码放在 `src/`，按页面、组件、状态、服务拆分。
- 后端主代码放在 `server/src/modules/`，按模块拆分 controller、service、dto。
- 文档统一放在 `docs/`。
- 脚本统一放在 `scripts/`。
- 基础设施目录保留在仓库根目录，如 `server/`、`public/`、`api/`、`data/`。
- 运行时缓存、浏览器会话、临时产物不作为业务代码目录使用。

## 前端边界
- 页面层只负责展示和页面编排，复杂逻辑优先下沉到 `lib/`、`store/` 或独立模块。
- 通用 UI 放在 `src/components/ui/`。
- 业务组件按领域放在 `src/components/<domain>/`。
- 接口请求统一收口到 `src/lib/`，不要把请求散落到页面里。
- 状态管理统一收口到 `src/store/`，避免页面之间复制状态逻辑。

## 后端边界
- 每个领域功能优先在 `server/src/modules/<module>/` 内闭环。
- controller 只处理请求、响应和参数校验，不承载业务逻辑。
- service 负责业务编排，不直接把接口细节扩散到其他模块。
- dto 只放输入输出约束，不混入业务逻辑。
- 数据访问统一经 Prisma 收口，避免到处直接拼数据库行为。

## 环境文件边界
- 根目录环境文件负责基础设施与容器相关变量。
- `server/.env.example` 负责后端运行所需变量。
- 示例文件只放占位值和开发默认值，不放真实密钥。
- 本地真实环境文件使用 `.env`，不提交到 Git。
- 环境变量命名保持稳定，优先复用已有键名，不随意新增同义变量。

## 运行时文件规则
- `server/.runtime/` 只允许放运行时缓存、会话与排查脚本，不作为正式代码目录。
- 运行时目录里的缓存、浏览器 session、临时素材不纳入业务交付内容。
- 遇到 `.runtime` 脏文件，优先清理运行时残留，不把问题误判为业务代码变更。

## 联调与请求失败排查
- 只要涉及前后端联调、登录、发布、权限、列表加载、保存提交，汇报“已完成”前必须先做服务自检。
- 服务自检最少包含：前端页面可访问、后端进程存活、后端健康接口可访问。
- 后端健康检查默认先验证 `http://127.0.0.1:3000/api/health`；连不上时，不允许直接把结果归因到业务代码。
- 前端开发环境默认先验证本地开发端口是否可访问；前端未启动时，不允许直接汇报“请求失败已修复”。
- 如果前后端任一服务未启动、已退出、端口不通、代理未生效，必须先说明这是环境或进程问题，再继续排查业务问题。
- 只要用户反馈“请求失败”，第一步先查服务状态与健康接口，第二步再查接口日志和业务代码。
- 未完成最小自检前，不得笼统汇报“已修复”“已打通”“可以使用”。

## 清理规则
- 无用文档、废弃脚本、调试残留、未引用组件及时清理。
- 相同职责的配置和说明保留一份，不保留重复版本。
- 新增文件前先判断是否已有合适目录，避免目录膨胀。
- 删除文件前先确认是运行时残留、未使用文件或已被替代内容。
