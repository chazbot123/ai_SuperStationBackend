# 统一授权中心方案

## 1. 目标

- 新建独立授权中心，固定域名为 `auth.jizhidaoai.com`
- 抖音、快手、B站、微信公众号统一走官方 OAuth
- 小红书、视频号继续走浏览器扩展登录与浏览器扩展发布
- 适配多客户交付，不要求每个客户单独注册开放平台应用
- 保持客户项目仍可在本地数据库中看到并使用已授权的平台账号

## 2. 适用边界

- 纳入授权中心：
  - 抖音
  - 快手
  - B站
  - 微信公众号
- 不纳入授权中心：
  - 小红书
  - 视频号
- 当前目标不包含：
  - 小红书官方 OAuth
  - 视频号官方 OAuth
  - 授权中心统一代替客户项目执行所有发布

## 3. 总体结论

- 授权中心应作为独立项目建设，不与当前业务后端直接混写
- 授权中心数据库保留官方 OAuth 主数据
- 客户项目数据库保留可发布、可展示的本地镜像数据
- 多客户隔离先采用一套授权中心数据库 + 多租户字段隔离
- 大客户如有合规要求，再单独扩展为单客户独立库

## 4. 推荐架构

### 4.1 系统拆分

- 客户项目
  - 负责后台页面、账号列表、本地发布任务、业务数据
- 授权中心 `auth.jizhidaoai.com`
  - 负责生成 OAuth 地址
  - 负责接平台回调
  - 负责换取和刷新 token
  - 负责租户隔离与授权结果分发
- 平台开放平台
  - 抖音、快手、B站、微信公众号

### 4.2 核心链路

1. 客户项目请求授权中心发起授权
2. 授权中心生成带租户信息的 `state`
3. 浏览器跳转平台授权页
4. 平台回调到 `auth.jizhidaoai.com`
5. 授权中心换 token、拉资料、落主库
6. 授权中心生成一次性 `grantCode`
7. 浏览器跳回客户项目
8. 客户项目服务端用 `grantCode` 向授权中心拉取授权结果
9. 客户项目把账号信息写入本地平台账号表

## 5. 项目形态

### 5.1 是否单独建项目

- 是
- 建议新建独立目录，例如：
  - `auth-center/`
- 不建议直接塞进当前 `server`

### 5.2 原因

- 当前业务后端已经承载客户管理、商品、AI、发布、客服等模块
- 授权中心是跨客户、跨实例、跨平台的公共基础服务
- 后续 token 刷新、租户校验、回调白名单、审计日志都应独立维护

## 6. 数据隔离方案

### 6.1 默认方案

- 一套授权中心数据库
- 按以下维度逻辑隔离：
  - `tenantId`
  - `instanceId`
  - `localUserId`
  - `platform`
  - `externalAccountId`

### 6.2 隔离规则

- 所有授权记录必须强制带 `tenantId`
- 所有部署实例必须强制带 `instanceId`
- 所有回跳地址必须在实例白名单内
- 所有授权结果查询都必须同时校验：
  - `tenantId`
  - `instanceId`
  - `grantCode`
- 不允许通过前端自由指定任意 `returnUrl`

### 6.3 是否每客户一个数据库

- 当前不建议
- 先采用统一库 + 多租户逻辑隔离
- 仅在以下情况再升级为独立库：
  - 客户明确要求物理隔离
  - 监管或审计要求必须独立存储
  - 客户量级大到需要单独运维

## 7. 数据主从策略

### 7.1 主数据归属

- 授权中心数据库是 OAuth 主数据源
- 客户项目数据库是业务镜像数据源

### 7.2 是否写回客户项目数据库

- 是，必须写回

### 7.3 原因

- 当前客户项目的平台账号列表依赖本地数据库展示
- 当前官方发布链路仍计划在客户项目中执行
- 如果不写回，客户项目无法直接使用已授权账号发布

### 7.4 推荐写回字段

- `platform`
- `externalAccountId`
- `displayName`
- `avatarUrl`
- `status`
- `scope`
- `expiresAt`
- `authCenterGrantId`
- `accessToken`
- `refreshToken`
- `provider = official_oauth`

### 7.5 为什么授权中心还要保留主数据

- 方便统一刷新 token
- 方便补偿同步
- 方便后续把部分官方发布能力再收口到中心
- 某个客户实例重装后可重新拉取授权结果

## 8. 推荐数据模型

### 8.1 授权中心表

- `auth_tenants`
  - 客户主表
- `auth_instances`
  - 客户实例表
  - 保存实例标识、回跳域名、回调白名单、同步密钥
- `oauth_sessions`
  - 授权会话
  - 保存 `state`、平台、租户、实例、发起用户、状态、过期时间
- `oauth_grants`
  - 授权结果主表
  - 保存 token、刷新时间、作用域、平台账号标识
- `oauth_profiles`
  - 平台账号资料缓存
  - 保存昵称、头像、账号号、附加资料
- `oauth_sync_logs`
  - 写回客户项目日志
  - 保存成功、失败、重试次数、错误信息

### 8.2 当前客户项目补充字段

- 在平台账号表增加：
  - `authCenterGrantId`
  - `authCenterTenantId`
  - `authCenterInstanceId`
  - `tokenSyncedAt`
  - `tokenExpiresAt`

## 9. 安全设计

### 9.1 回传方式

- 不把 token 直接拼到浏览器回调 URL
- 只返回一次性 `grantCode`

### 9.2 推荐流程

1. 授权中心完成授权后生成一次性 `grantCode`
2. 浏览器跳回客户项目地址，并带上 `grantCode`
3. 客户项目服务端调用授权中心接口换取授权结果
4. 客户项目写本地数据库

### 9.3 必做安全项

- token 加密存储
- `grantCode` 设置短过期时间
- `state` 防重放
- `returnUrl` 白名单校验
- 客户项目与授权中心之间使用签名或共享密钥
- 所有同步操作记录审计日志

## 10. 与当前项目的职责划分

### 10.1 授权中心负责

- 平台 OAuth 发起
- 平台回调处理
- token 换取
- token 刷新
- 平台账号资料拉取
- 授权结果分发

### 10.2 当前客户项目负责

- 展示平台账号列表
- 触发授权入口
- 接收授权结果
- 本地保存平台账号
- 执行抖音、快手、B站、公众号的官方发布
- 继续执行小红书、视频号的扩展发布

## 11. 推荐接口设计

### 11.1 客户项目 -> 授权中心

- `POST /api/tenants/:tenantId/oauth/start`
  - 入参：
    - `instanceId`
    - `localUserId`
    - `platform`
    - `returnPath`
  - 返回：
    - `loginUrl`

### 11.2 平台 -> 授权中心

- `GET /api/oauth/callback/:platform`
  - 接收 `code`
  - 接收 `state`

### 11.3 客户项目 -> 授权中心拉结果

- `POST /api/oauth/grants/exchange`
  - 入参：
    - `grantCode`
    - `tenantId`
    - `instanceId`
  - 返回：
    - 平台账号资料
    - token 信息
    - 过期时间

### 11.4 授权中心 -> 客户项目可选回推

- `POST /api/internal/auth-center/grants/sync`
  - 作为补偿机制
  - 不作为首版主链路

## 12. 实施阶段

### 阶段 1：授权中心最小骨架

- 新建独立项目
- 建数据库
- 建租户、实例、授权会话、授权结果表
- 接通抖音 OAuth

### 阶段 2：客户项目接入

- 当前项目新增“向授权中心申请授权地址”接口
- 当前项目新增“用 `grantCode` 换授权结果并写平台账号”接口
- 平台账号表增加授权中心关联字段

### 阶段 3：扩平台

- 接入快手
- 接入 B站
- 接入微信公众号

### 阶段 4：稳定化

- token 自动刷新
- 同步补偿
- 审计日志
- 租户回跳白名单

## 13. 当前最小落地建议

- 先只做授权中心方案，不立即迁所有发布逻辑
- 授权中心首版只负责：
  - 发起授权
  - 接回调
  - 保存 token
  - 把结果同步给当前项目
- 当前项目继续保留：
  - 平台账号列表页
  - 官方发布执行逻辑
  - 小红书/视频号扩展链路

## 14. 最终建议

- `auth.jizhidaoai.com` 应作为统一授权中心域名长期保留
- 授权中心单独建项目，不混入当前业务后端
- 数据隔离先走统一库 + 多租户逻辑隔离
- 授权中心保留主数据，客户项目必须保留本地镜像数据
- 官方 OAuth 平台统一收口到授权中心
- 小红书、视频号继续保持浏览器扩展链路
