# AI 超级站（前台 + 后台）V1.4 PRD

> 版本：V1.4  
> 日期：2026-04-20  
> 文档类型：Markdown 版 PRD  
> 变更主题：企业名片、认证会话、商品英文名

---

## 1. 变更背景

本次 PRD 更新围绕以下 3 个方向展开：

- 企业名片系统正式纳入后台账号体系，每个账号一张名片，并支持小程序 / H5 / 前台名片页复用
- 登录体系补充 session 语义，明确最多 2 台设备在线及第 3 台设备挤掉最早设备
- 商品对象正式支持英文名字段，统一覆盖创建、编辑、列表、搜索与保存

---

## 2. 目标与范围

### 2.1 本次目标

- 明确认证登录后的 session 创建、设备限制和手动下线能力
- 明确商品英文名的生成、人工修正和全链路使用规则

- 后端接口契约

- 前端 store 契约

## 4. 接口变更表

### 4.1 企业名片接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/business-cards/me` | 获取当前登录用户自己的名片 |
| PUT | `/api/business-cards/me` | 更新当前登录用户自己的名片 |
| GET | `/api/business-cards/:userId` | 获取指定用户的名片展示信息 |
| POST | `/api/business-cards/me/cover` | 上传名片封面图 |

### 4.2 认证 / 会话接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/login` | 登录，登录成功创建 session |
| POST | `/api/auth/logout` | 当前设备退出登录 |
| GET | `/api/auth/me` | 获取当前用户信息、角色、权限、数据范围 |
| GET | `/api/auth/sessions` | 当前账号在线设备列表 |
| DELETE | `/api/auth/sessions/:id` | 手动下线某一台设备 |

### 4.3 商品接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/products` | 商品列表，支持英文名 |
| POST | `/api/products` | 创建商品，支持英文名 |
| GET | `/api/products/:id` | 商品详情，支持英文名 |
| PUT | `/api/products/:id` | 更新商品，支持英文名 |
| DELETE | `/api/products/:id` | 删除商品 |
| POST | `/api/products/:id/submit` | 提交审核 |
| PUT | `/api/products/:id/special-offer` | 更新特价配置 |
| POST | `/api/products/infer-english-name` | 根据中文产品名生成英文名 |

## 5. 业务规则变更表

### 5.1 企业名片

| 规则编号 | 规则描述 |
|----------|----------|
| BC-01 | 每个账号一张名片 |
| BC-02 | 名片与后台账户强绑定 |
| BC-03 | 小程序名片系统复用后台账号密码登录 |
| BC-04 | 对外展示信息通过 `GET /api/business-cards/:userId` 获取 |
| BC-05 | 封面图独立上传，名片主数据与文件上传分离 |

### 5.2 商品英文名

| 规则编号 | 规则描述 |
|----------|----------|
| PR-01 | 中文产品名自动生成英文产品名 |
| PR-02 | 用户可以手动调整 |
| PR-03 | 列表、搜索、保存统一支持英文名 |
| PR-04 | 接口主字段使用 `englishName`，兼容 `english_name` |

### 5.3 登录设备限制

| 规则编号 | 规则描述 |
|----------|----------|
| AU-01 | 最多 2 台设备同时在线 |
| AU-02 | 第 3 台登录挤掉最早设备 |
| AU-03 | 登录成功必须创建 session |
| AU-04 | 登出仅退出当前设备 |
| AU-05 | 支持查看在线设备列表 |
| AU-06 | 支持手动下线指定设备 |
| AU-07 | 登录不做固定时效主动过期 |

## 6. 前端 Store 对齐

当前业务契约要求前端 Demo 对齐以下能力：

| 领域 | Store 方法 | 说明 |
|------|------------|------|
| 企业名片 | `ensureBusinessCard(userId)` | 首次访问确保名片存在 |
| 企业名片 | `updateBusinessCard(userId, payload)` | 更新名片 |
| 企业名片 | `getBusinessCardByUserId(userId)` | 获取公开展示名片 |
| 商品英文名 | `inferEnglishProductName(name)` | 生成英文名 |
| 商品创建 | `addProduct()` | 创建商品时自动回填 `englishName` |

## 7. 页面与渠道影响

### 7.1 后台

- 登录页需要体现设备会话语义
- 产品管理页需要展示并搜索英文名
- 企业名片页需要支持封面上传、模板选择、预览与保存

### 7.2 小程序 / H5 / 前台

- 名片页通过 `userId` 拉取展示数据
- 名片页复用后台账户体系，不单独再建账号系统

---

## 8. 验收标准

- 企业名片接口覆盖“自己读、自己改、他人展示、封面上传”四种场景
- 登录后产生 session，且账号同时在线设备数不超过 2
- 第 3 台设备登录后，最早设备被自动下线
- 商品对象在接口层统一返回英文名
- 商品列表支持按中文名和英文名检索
- 前端创建商品时可以自动带出英文名并允许人工修改
